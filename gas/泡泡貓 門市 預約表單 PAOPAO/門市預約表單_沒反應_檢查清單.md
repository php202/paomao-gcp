# 門市預約表單 PAOPAO「都沒有做反應」檢查清單

當在 LINE 群組（例如 Robby Yu, PAOPAO）傳「測試」「店家回覆狀態」等訊息，bot 完全沒回覆時，請依序檢查以下項目。

---

## 1. 確認是哪一隻 Bot 在群組裡

- 截圖顯示「泡泡貓‐行政請款」被加入又移出，**那是另一隻**（行政請款）。
- 若群組名稱是「Robby Yu, PAOPAO (2)」，表示群裡有 **門市預約表單 PAOPAO** 這隻官方帳號。
- **只有「門市預約表單 PAOPAO」這隻**會處理「店家回覆狀態」並寫入「訊息一覽」；行政請款是不同頻道、不同 Webhook。

---

## 2. LINE Developers：Webhook URL 指到哪裡？

1. 登入 [LINE Developers](https://developers.line.biz/)。
2. 選 **Provider** → 選 **門市預約表單 PAOPAO** 對應的 **Channel**（Messaging API）。
3. 在 **Messaging API** 分頁找到 **Webhook URL**。

**必須是以下其中一個：**

| 後端 | Webhook URL 範例 |
|------|-------------------|
| **GAS** | `https://script.google.com/macros/s/門市預約表單的部署ID/exec` |
| **GCP** | `https://你的Cloud Run網址/paopao-line-webhook` |

- 若這裡是**空白**、**錯誤網址**、或指到**員工打卡**的 URL → LINE 不會把訊息送給門市預約表單，**一定不會有反應**。
- 若已改由 GCP 處理，請確認填的是 **GCP 的 `/paopao-line-webhook`**，不是 `/line-webhook`（那是員工打卡用）。

---

## 3. 若 Webhook 指到 GAS（門市預約表單 Web App）

- 確認「泡泡貓 門市 預約表單 PAOPAO」專案已 **部署為網路應用程式**（執行身份：我、存取權：任何人）。
- 確認 **PaoMao_Core 程式庫** 已正確加入且可執行（Core.getCoreConfig、Core.getDirectStoreReplyStatusText 等）。
- 到 GAS 編輯器：**執行** → 選 `doPost`（需用 Post 模擬），或從 **檢視** → **執行紀錄** 看是否有錯誤。
- 若執行時出現權限錯誤、找不到試算表、或 Core 未定義，bot 就不會回覆。

---

## 4. 若 Webhook 指到 GCP（/paopao-line-webhook）

在 GCP 專案（Cloud Run / 環境變數）確認：

| 變數 | 說明 | 沒設的結果 |
|------|------|------------|
| `PAOPAO_STORE_SS_ID` | 門市預約表單試算表 ID | 回 200 但不處理事件、不回覆 |
| `LINE_CHANNEL_SECRET_PAOPAO` | 門市預約表單的 Channel Secret | 簽章驗證失敗 → 401，不回覆 |
| `LINE_TOKEN_PAOPAO` | 門市預約表單的 Channel Access Token | 無法呼叫 LINE Reply API，不回覆 |
| `LINE_STORE_SS_ID` | 各店訊息一覽表 ID（店家回覆狀態用） | 「店家回覆狀態」會回「需設定 LINE_STORE_SS_ID」 |

- 試算表 **PAOPAO_STORE_SS_ID** 必須有 **「訊息一覽」** 工作表，且 Service Account 有編輯權限。
- 部署後可對 Cloud Run 發 GET：`https://你的網址/paopao-line-webhook`，應回 `{"status":"ok","message":"PAOPAO LINE Webhook endpoint exists. Use POST."}`。

---

## 5. 行為對照

| 訊息內容 | 預期行為 |
|----------|----------|
| 「測試」 | **不會回覆**（門市預約表單設計上不對一般文字回話），但應會寫入試算表「訊息一覽」。 |
| 「店家回覆狀態」 | **會回覆**：管理者回店家回覆狀態文字；非管理者回「此功能僅限管理者使用。」 |

若「店家回覆狀態」也沒回覆，代表 Webhook 沒進到正確後端，或後端執行失敗／未設定 Token 或 Secret。

---

## 6. 建議立刻檢查的一項

**到 LINE Developers → 門市預約表單 PAOPAO 的 Channel → Messaging API → Webhook URL：**

- 若是空白 → 請填上 GAS 或 GCP 的 Webhook URL 並儲存。
- 若填的是員工打卡的 URL → 請改成門市預約表單專用的 URL（GAS 部署網址或 GCP `/paopao-line-webhook`）。
- 儲存後可再傳一次「店家回覆狀態」測試。

完成上述檢查後，若仍沒反應，可再查 GAS 執行紀錄或 GCP Cloud Run 日誌，確認是否有收到 POST 或錯誤訊息。
