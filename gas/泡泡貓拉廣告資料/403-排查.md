# Core API 403 無權存取 — 排查步驟

已將 PaoMao_Core「誰可以存取」改為「任何人」仍出現 403 時，請依序確認以下項目。

---

## 1. 確認改的是「正確的那一筆」部署

- 在 **PaoMao_Core** 專案：**部署** → **管理部署**。
- 會看到多筆（例如「測試部署」、或多個版本）。
- **只有「類型＝網路應用程式」且「網址結尾是 `/exec`」的那一筆**才要設成「任何人」。
- 若你改的是「測試部署」或別的類型，不會影響泡泡貓拉廣告資料實際呼叫的網址，所以仍會 403。
- **對照網址**：本專案指令碼屬性 `PAO_CAT_CORE_API_URL` 必須與「你要改的那一筆」的網址**完全一致**（含 `/exec`，不能是 `/dev` 或 `/edit`）。

---

## 2. 必須選「任何人」，不能選「擁有 Google 帳戶的任何人」

- **誰可以存取** 下拉選單通常有兩項容易搞混：
  - **「任何人」**（英文：Anyone）→ ✅ 正確。未登入的請求（例如另一支 GAS 用 UrlFetchApp 打來）也能通過。
  - **「擁有 Google 帳戶的任何人」**（英文：Anyone with Google account）→ ❌ 會 403。因為從另一支 GAS 打過來的請求不會帶「你的 Google 登入」，會被當成匿名而拒絕。
- 請在「管理部署」→ 編輯該筆 → 確認選的是 **「任何人」**，不是「擁有 Google 帳戶的任何人」。

## 3. 改完後有按「部署」儲存嗎？

- 在「管理部署」裡編輯時，把「誰可以存取」改為「任何人」後，**必須按下方「部署」按鈕**才會儲存。
- 只改下拉選單就關閉視窗，設定不會生效。

---

## 4. 用本專案診斷函式確認網址與結果

1. 開啟 **泡泡貓拉廣告資料** 的 Apps Script 編輯器。
2. 在編輯器上方函式選單選擇 **`runCoreApi403Check`**，按「執行」。
3. 執行完後點 **執行紀錄**（或「檢視」→「紀錄」）：
   - 會印出你目前設定的 **Core API 網址**（無 key），請與 PaoMao_Core「管理部署」中「網路應用程式」那筆的 URL 逐字對照是否一致。
   - 會用 **`?action=storeList`**（不需 key）打一次該網址：
     - 若顯示 **HTTP 200**：代表「該網址」的部署已開放，若實際跑預約仍 403，多半是網址設錯（例如設成別筆或 /dev）。
     - 若顯示 **HTTP 403**：代表「該網址」對應的部署仍未被允許存取，請回到 PaoMao_Core 對「這一筆 URL」改為「任何人」並按「部署」儲存。

---

## 5. 用瀏覽器直接測同一網址（可選）

- 在**無痕視窗**或未登入 Google 的瀏覽器開：
  - `你設定的 Core API 網址?action=storeList`
  - 例：`https://script.google.com/macros/s/AKfycby5ibTcUxvPD-Xj1-lOHOJ5oI27CbyyaHv2K3cvNd1PwMiPvwGCpjlzi6UbW4fwip2UaA/exec?action=storeList`
- 若出現 **JSON（門市列表）**：該部署已開放。
- 若出現 **「You need access」/ 403 頁**：該部署的「誰可以存取」仍非「任何人」，或你開的網址與「管理部署」裡那筆不一致。

---

## 6. 確認網址不是「測試部署」

- **正式部署**網址長相：`https://script.google.com/macros/s/<一串ID>/exec`
- **測試部署**通常是：`.../dev` 或不同 ID。
- 本專案指令碼屬性 **PAO_CAT_CORE_API_URL** 一定要填「正式部署」的網址（結尾 `/exec`），不要填測試部署。

---

## 7. Google Workspace 組織政策（若適用）

- 若 PaoMao_Core 在 **Google Workspace** 底下，管理員可能限制了「對外分享」或「Web App 存取」。
- 若上述都確認無誤仍 403，請由管理員檢查是否封鎖了「任何人」存取 Apps Script Web App。

---
