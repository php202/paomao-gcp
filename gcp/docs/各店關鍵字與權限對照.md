# 各店訊息一覽表（Paomao 客人 LINE）關鍵字與權限對照

GCP 目前**未**處理各店 webhook（無 store-line-webhook 或等同路由）。本表整理 GAS 行為，供下次測試對照與未來搬移用。

**來源**：gas/各店訊息一覽表 Post-handleLineWebhook.js、messFilter 規則、KeywordReports.js（報告關鍵字已不在客人 LINE 回應）。

---

## 一、事件類型與權限

| 類型 | 關鍵字／條件 | 權限／對象 | 行為（GAS） |
|------|--------------|------------|-------------|
| postback | `action=book_reengagement` | 客人 | handleReengagementBooking |
| 篩選（messFilter） | 我的會員、課程介紹、送出預約、線上預約、您已取消預約 | 依規則 | 見下表 |
| 報告關鍵字 | 昨日報告、明日預約、本月報告、員工樣態等 | 已移至員工打卡，客人 LINE **不回應** | - |
| 其他文字 | 任意 | 寫入訊息一覽、擷取手機等 | 寫入試算表、syncLineUserId 等 |

---

## 二、messFilter 細則

| 關鍵字 | 不寫挽留 | 不寫訊息一覽 | Reply |
|--------|----------|--------------|-------|
| 我的會員 | - | - | 不 Reply |
| 課程介紹 | - | - | 不 Reply |
| 送出預約 | - | - | 不 Reply |
| 線上預約 | - | - | 查空位 + 可 Reply（I 欄 isReply） |
| 您已取消預約 | - | - | 不 Reply |
| 其他任意文字 | - | - | 寫入「訊息一覽」試算表 |

---

## 三、權限說明

- 各店以「店家」為單位（storeInfo、token、sayId），由 findStoreConfig 辨識。
- 無「員工／管理者」角色，僅區分是否為已知店家、是否 Reply。
- 報告關鍵字（昨日報告、明日預約、本月報告、員工樣態）已移至員工打卡 Line@，客人 LINE 不回應。

---

## 四、未來 GCP 搬移時

若 GCP 接各店 webhook，請依本表與 GAS Post-handleLineWebhook.js、messFilter、addToRetentionList 等邏輯對齊實作。
