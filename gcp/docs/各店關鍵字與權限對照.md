# 各店訊息一覽表（Paomao 客人 LINE）關鍵字與權限對照

**各店 LINE Webhook 已統一使用 GCP 入口**：請在 LINE Developers 將各店頻道的 Webhook URL 設為 Cloud Run `https://<服務網址>/store-line-webhook`。GAS 各店訊息一覽表仍保留 Web App（查詢空位 searchAvailability、挽留清單等），不再作為 LINE Webhook 接收端。

**來源**：GCP api/store-line-webhook.js、gas/各店訊息一覽表 Post-handleLineWebhook.js（邏輯對照）、KeywordReports.js（報告關鍵字已不在客人 LINE 回應）。

---

## 一、事件類型與權限

| 類型 | 關鍵字／條件 | 權限／對象 | 行為（GAS） |
|------|--------------|------------|-------------|
| postback | `action=book_reengagement` | 客人 | handleReengagementBooking |
| 篩選（messFilter） | 我的會員、課程介紹、送出預約、線上預約、您已取消預約 | 依規則 | 見下表 |
| 報告關鍵字 | 昨日報告、明日預約、本月報告、員工樣態等 | 已移至員工打卡，客人 LINE **不回應** | - |
| 其他文字 | 任意 | 寫入訊息一覽、擷取手機等 | 寫入試算表、syncLineUserId 等 |

---

## 二、messFilter 細則

| 關鍵字 | 不寫挽留 | 不寫訊息一覽 | Reply |
|--------|----------|--------------|-------|
| 我的會員 | - | - | 不 Reply |
| 課程介紹 | - | - | 不 Reply |
| 送出預約 | - | - | 不 Reply |
| 線上預約 | - | - | 查空位 + 可 Reply（I 欄 isReply） |
| 您已取消預約 | - | - | 不 Reply |
| 其他任意文字 | - | - | 寫入「訊息一覽」試算表 |

---

## 三、權限說明

- 各店以「店家」為單位（storeInfo、token、sayId），由 findStoreConfig 辨識。
- 無「員工／管理者」角色，僅區分是否為已知店家、是否 Reply。
- 報告關鍵字（昨日報告、明日預約、本月報告、員工樣態）已移至員工打卡 Line@，客人 LINE 不回應。

---

## 四、各店 Webhook 使用 GCP 時

- Webhook URL：`https://<Cloud Run 服務網址>/store-line-webhook`（與員工 `/line-webhook` 同服務、不同 path）。
- 部署後於 LINE Developers **每一店**頻道將 Webhook URL 改為上述網址，才算是「都牽至 GCP」。
- **如何確認已走 GCP**：客人發「線上預約」後，若「都滿了」時回覆有「（除錯：…；請將此整則訊息貼給管理員）」即為 GCP；沒有該行則仍走 GAS，請改 Webhook URL。詳見 [各店訊息一覽表-Webhook-GCP入口.md](各店訊息一覽表-Webhook-GCP入口.md)。
- 實作已與 GAS Post-handleLineWebhook.js、messFilter、addToRetentionList 等邏輯對齊。
