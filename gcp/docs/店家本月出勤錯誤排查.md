## 1. 錯誤代碼（建議優先）

若程式已部署**含錯誤代碼**的版本，LINE 回覆會多一行：

```
（錯誤代碼：20260216_143022_8k2m，提供此代碼可加速排查）
```

請把**錯誤代碼**提供給管理員。管理員在 GCP Logging 搜尋該代碼（例如 `20260216_143022_8k2m`）即可找到對應的完整錯誤內容（`message`、`stack`、`responseData` 等）。

## 2. GCP Cloud Logging 搜尋

管理員可到 **Google Cloud Console → Logging → Logs Explorer**，在查詢欄位使用：

- 依錯誤代碼搜尋（若有）：  
  `jsonPayload.message=~"錯誤代碼對應的那一串"`  
  或直接搜尋文字：`createAttendanceSpreadsheetAndShare failed` 加上該錯誤代碼。

- 若尚無錯誤代碼，可依功能與時間篩選：  
  `textPayload=~"[handleAttendanceCommand]" OR textPayload=~"[attendance-sheet]"`  
  再依發生時間縮小範圍。

單筆錯誤 log 會包含：

- `errorId`：錯誤代碼  
- `feature`：`"店家本月出勤"`  
- `userId`：觸發者的 LINE userId  
- `yyyyMM`：查詢月份（如 `2026-02`）  
- `message`：錯誤訊息  
- `stack`：堆疊  
- `responseData`：Google API 回傳的錯誤細節（若有）

## 3. 你可先提供的資訊（無需進 GCP 時）

若你無法查 GCP Logging，可先提供給管理員：

- **發生時間**：約幾月幾日、幾點（可含時區，例如台北時間）。  
- **錯誤代碼**：LINE 回覆裡的那一串（若已有顯示）。  
- **操作**：例如「點『店家本月出勤』後出現錯誤」。

管理員即可用「時間 + 錯誤代碼」或「時間 + userId」在 Logging 裡找到對應記錄。

## 4. 常見錯誤來源（給開發／管理員）

- **建立試算表失敗**：`[attendance-sheet] spreadsheets.create failed` — 多與 Google 帳號權限、配額或專案設定有關。  
- **寫入工作表失敗**：`[attendance-sheet] writeSheet failed` — 某店名稱或資料寫入 Sheets API 時失敗，log 會有 `sheetIndex`、`sheetTitle`。  
- 上述錯誤都會在 handler 的 catch 中統一記錄為 `createAttendanceSpreadsheetAndShare failed` 並帶上 `errorId`。

## 5. 「The caller does not have permission」處理步驟

錯誤訊息為 **建立試算表失敗: The caller does not have permission** 時，表示用來呼叫 Google API 的 identity（服務帳號或 Cloud Run 執行身分）沒有「建立新試算表」的權限。新試算表會建立在該 identity 的 Drive 中，需同時啟用 **Sheets API** 與 **Drive API**。

**Log 顯示 `caller: (no client_email)` 或 `caller: (ADC, ...)` 時**：代表目前用的是 Cloud Run 的執行服務帳號（例如 paomao），請在**同一個專案**啟用 **Google Drive API**。

### 5.1 一定要做：啟用 Google Drive API

1. 開啟：  
   **https://console.cloud.google.com/apis/library/drive.googleapis.com?project=gen-lang-client-0828139766**  
   （若專案不同，改網址中的 `project=你的專案ID`）
2. 若頁面按鈕是 **「啟用」** → 點下去，等幾秒直到變成「管理」。
3. 若按鈕是 **「管理」** → 表示已啟用，請再確認 **Google Sheets API** 也已啟用：  
   https://console.cloud.google.com/apis/library/sheets.googleapis.com?project=gen-lang-client-0828139766

### 5.2 其餘檢查

請依序檢查：

1. **已啟用 API**  
   - **API 與服務** → **已啟用的 API 和服務**。  
   - 清單中需同時有：  
     - **Google Sheets API**  
     - **Google Drive API**  
   - 若缺少任一個，到「API 程式庫」搜尋並點「啟用」。

2. **確認 Cloud Run 使用的身份**  
   - **Cloud Run** → 選服務 `pao-checkin-api` → **修訂版本** → 點目前修訂 → **安全性**。  
   - 若使用「預設」：實際身份為專案的 **Compute Engine 預設服務帳號**（`PROJECT_NUMBER-compute@developer.gserviceaccount.com`）。  
   - 若使用自訂服務帳號：記下該帳號的 email。

3. **自訂服務帳號權限（若有使用）**  
   - **IAM 與管理** → **IAM**，找到上述服務帳號。  
   - 至少需能使用 API（例如 **編輯者** 或具 **Service Account User** + 專案層級可呼叫 Sheets/Drive）。  
   - 若專案有組織政策限制「服務帳號建立檔案」，需由管理員放行或改用有權限的服務帳號。

4. **使用金鑰檔（GOOGLE_APPLICATION_CREDENTIALS）時**  
   - 確認金鑰檔對應的服務帳號所屬專案已啟用 **Sheets API** 與 **Drive API**。  
   - 該服務帳號無需被「共用試算表」；建立試算表會建立在其自己的 Drive 中。

6. **專案計費**  
   - Drive API / Sheets API 建立新檔案時，**專案通常需已啟用計費**（即使用量在免費額度內）。  
   - **Google Cloud Console** → 左上選專案 → **帳單**（或 [console.cloud.google.com/billing](https://console.cloud.google.com/billing)）→ 確認此專案已連結到帳單帳戶。若未連結，請連結後再試。

完成後重新觸發「店家本月出勤」測試；若仍出現 permission 錯誤，請把最新 log 的 `message` 與 `responseData` 提供給管理員。

---

**小結**：請盡量提供 LINE 上顯示的**錯誤代碼**與**發生時間**，管理員即可在 GCP Logging 中快速定位並修正。
