## 1. 錯誤代碼（建議優先）

若程式已部署**含錯誤代碼**的版本，LINE 回覆會多一行：

```
（錯誤代碼：20260216_143022_8k2m，提供此代碼可加速排查）
```

請把**錯誤代碼**提供給管理員。管理員在 GCP Logging 搜尋該代碼（例如 `20260216_143022_8k2m`）即可找到對應的完整錯誤內容（`message`、`stack`、`responseData` 等）。

## 2. GCP Cloud Logging 搜尋

管理員可到 **Google Cloud Console → Logging → Logs Explorer**，在查詢欄位使用：

- 依錯誤代碼搜尋（若有）：  
  `jsonPayload.message=~"錯誤代碼對應的那一串"`  
  或直接搜尋文字：`createAttendanceSpreadsheetAndShare failed` 加上該錯誤代碼。

- 若尚無錯誤代碼，可依功能與時間篩選：  
  `textPayload=~"[handleAttendanceCommand]" OR textPayload=~"[attendance-sheet]"`  
  再依發生時間縮小範圍。

單筆錯誤 log 會包含：

- `errorId`：錯誤代碼  
- `feature`：`"店家本月出勤"`  
- `userId`：觸發者的 LINE userId  
- `yyyyMM`：查詢月份（如 `2026-02`）  
- `message`：錯誤訊息  
- `stack`：堆疊  
- `responseData`：Google API 回傳的錯誤細節（若有）

## 3. 你可先提供的資訊（無需進 GCP 時）

若你無法查 GCP Logging，可先提供給管理員：

- **發生時間**：約幾月幾日、幾點（可含時區，例如台北時間）。  
- **錯誤代碼**：LINE 回覆裡的那一串（若已有顯示）。  
- **操作**：例如「點『店家本月出勤』後出現錯誤」。

管理員即可用「時間 + 錯誤代碼」或「時間 + userId」在 Logging 裡找到對應記錄。

## 4. 常見錯誤來源（給開發／管理員）

- **建立試算表失敗**：`[attendance-sheet] spreadsheets.create failed` — 多與 Google 帳號權限、配額或專案設定有關。  
- **寫入工作表失敗**：`[attendance-sheet] writeSheet failed` — 某店名稱或資料寫入 Sheets API 時失敗，log 會有 `sheetIndex`、`sheetTitle`。  
- 上述錯誤都會在 handler 的 catch 中統一記錄為 `createAttendanceSpreadsheetAndShare failed` 並帶上 `errorId`。

## 5. 「The caller does not have permission」處理步驟

錯誤訊息為 **建立試算表失敗: The caller does not have permission** 時，表示用來呼叫 Google API 的 identity（服務帳號或 Cloud Run 執行身分）沒有「建立新試算表」的權限。新試算表會建立在該 identity 的 Drive 中，需同時啟用 **Sheets API** 與 **Drive API**。

**Log 顯示 `caller: (no client_email)` 或 `caller: (ADC, ...)` 時**：代表目前用的是 Cloud Run 的執行服務帳號（例如 paomao），請在**同一個專案**啟用 **Google Drive API**。

### 5.1 一定要做：啟用 Google Drive API

1. 開啟：  
   **https://console.cloud.google.com/apis/library/drive.googleapis.com?project=gen-lang-client-0828139766**  
   （若專案不同，改網址中的 `project=你的專案ID`）
2. 若頁面按鈕是 **「啟用」** → 點下去，等幾秒直到變成「管理」。
3. 若按鈕是 **「管理」** → 表示已啟用，請再確認 **Google Sheets API** 也已啟用：  
   https://console.cloud.google.com/apis/library/sheets.googleapis.com?project=gen-lang-client-0828139766

### 5.2 其餘檢查

請依序檢查：

1. **已啟用 API**  
   - **API 與服務** → **已啟用的 API 和服務**。  
   - 清單中需同時有：  
     - **Google Sheets API**  
     - **Google Drive API**  
   - 若缺少任一個，到「API 程式庫」搜尋並點「啟用」。

2. **確認 Cloud Run 使用的身份**  
   - **Cloud Run** → 選服務 `pao-checkin-api` → **修訂版本** → 點目前修訂 → **安全性**。  
   - 若使用「預設」：實際身份為專案的 **Compute Engine 預設服務帳號**（`PROJECT_NUMBER-compute@developer.gserviceaccount.com`）。  
   - 若使用自訂服務帳號：記下該帳號的 email。

3. **自訂服務帳號權限（若有使用）**  
   - **IAM 與管理** → **IAM**，找到上述服務帳號。  
   - 至少需能使用 API（例如 **編輯者** 或具 **Service Account User** + 專案層級可呼叫 Sheets/Drive）。  
   - 若專案有組織政策限制「服務帳號建立檔案」，需由管理員放行或改用有權限的服務帳號。

4. **使用金鑰檔（GOOGLE_APPLICATION_CREDENTIALS）時**  
   - 確認金鑰檔對應的服務帳號所屬專案已啟用 **Sheets API** 與 **Drive API**。  
   - 該服務帳號無需被「共用試算表」；建立試算表會建立在其自己的 Drive 中。

6. **專案計費**  
   - Drive API / Sheets API 建立新檔案時，**專案通常需已啟用計費**（即使用量在免費額度內）。  
   - **Google Cloud Console** → 左上選專案 → **帳單**（或 [console.cloud.google.com/billing](https://console.cloud.google.com/billing)）→ 確認此專案已連結到帳單帳戶。若未連結，請連結後再試。

完成後重新觸發「店家本月出勤」測試；若仍出現 permission 錯誤，請把最新 log 的 `message` 與 `responseData` 提供給管理員。

### 5.3 程式備援（Sheets 403 時改試 Drive API）

程式已實作：當 **Sheets API** `spreadsheets.create` 回 403 時，會自動改呼叫 **Drive API** `files.create`（mimeType: 試算表）建立檔案；若 Drive 成功，再以 Sheets API 新增各店工作表並寫入。若兩者皆 403，則需改由 **Secret Manager 掛載服務帳號金鑰**（見下）讓 Cloud Run 使用可建立檔案的 SA。

### 5.4 若 API 已啟用、計費已開仍 403（改用金鑰檔）

若專案已啟用 Sheets + Drive API 且已連結計費，執行身分（如 paomao-967）仍回 403，可改讓 Cloud Run 使用**具備權限的服務帳號金鑰**：

1. 在 IAM 建立或選一個可建立試算表的服務帳號，建立金鑰（JSON）。
2. 將金鑰內容存入 **Secret Manager**（例如 `sa-sheets-key`）。
3. 部署 Cloud Run 時掛載該 Secret 為檔案（如 `/secrets/sa-key.json`），並設環境變數 `GOOGLE_APPLICATION_CREDENTIALS=/secrets/sa-key.json`。
4. 重新部署後，建立試算表會改由該金鑰對應的 SA 執行。

### 5.5 LINE 顯示「可能原因：權限不足」時

若 LINE 已顯示錯誤代碼與「可能原因：權限不足」，請依序確認：

1. **Log 內是 Sheets 還是 Drive 失敗**  
   到 Logging 搜尋該錯誤代碼，看 `message`：  
   - 若為 **建立試算表失敗（Drive）: ...** → 是 Drive API 建立檔案時權限不足。  
   - 若為 **建立試算表失敗: ...**（無「Drive」）→ 是 Sheets API 先 403，Drive 備援可能未執行或也失敗。

2. **專案已啟用 API**  
   - [Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com?project=gen-lang-client-0828139766) → 需為「管理」。  
   - [Google Sheets API](https://console.cloud.google.com/apis/library/sheets.googleapis.com?project=gen-lang-client-0828139766) → 需為「管理」。

3. **Secret 內金鑰是 pao-sheets-creator**  
   - 部署使用 `SA_KEY_SECRET_NAME=pao-sheets-sa-key` 時，該 Secret 的**內容**必須是 **pao-sheets-creator** 的 JSON 金鑰（不是 paomao-967）。  
   - 若放錯成 paomao-967，仍會 403。到 **Secret Manager** → `pao-sheets-sa-key` → 新版本，上傳 **pao-sheets-creator** 的 JSON 後重新部署。

4. **Cloud Run 有掛載金鑰**  
   - Cloud Run → pao-checkin-api → 修訂版本 → 變數與密碼：  
     - 有 `GOOGLE_APPLICATION_CREDENTIALS=/secrets/sa-key.json`  
     - 有掛載 Secret `pao-sheets-sa-key` → `/secrets/sa-key.json`  
   - Log 應出現 `[auth] using keyFile: /secrets/sa-key.json`，且 `createSpreadsheet caller:` 為 **pao-sheets-creator@gen-lang-client-0828139766.iam.gserviceaccount.com**。

5. **員工試算表已分享給 pao-sheets-creator**  
   - 讀取員工清單、打卡紀錄的試算表（LINE_STAFF_SS_ID）需「知道連結的任何人可檢視」或已分享給 **pao-sheets-creator@...**，否則會先出現「你的帳號尚未開通」或讀取失敗，而非建立試算表失敗。

### 5.6 LINE 顯示「可能原因：Drive 儲存空間已滿」時

服務帳號（pao-sheets-creator）的 Google Drive 約 **15GB**，試算表建立太多會滿。程式會自動：

1. **多輪清理**：配額不足時，列出「自己擁有」的最舊試算表，每輪最多刪除 100 個，最多 5 輪，每刪一輪就重試建立；若無可刪或刪了仍滿，才回錯誤。
2. **Log 可查**：到 Logging 搜尋錯誤代碼，會看到 `Drive storage: usage= ... limit= ...`、`quota cleanup: found N owned spreadsheets, deleting oldest`、`deleted X files`。若 `found 0` 表示沒有 SA 擁有的試算表可刪（可能全是別人分享的），或刪除權限有問題。

**若清理後仍常滿，可改在「共用資料夾」建立（用該資料夾擁有者的配額）：**

1. 在**一般 Google 帳號**（例如公司帳號）的 Drive 建立一個資料夾，專門放出勤試算表。
2. 把該資料夾分享給 **pao-sheets-creator@gen-lang-client-0828139766.iam.gserviceaccount.com**，權限設為**編輯者**。
3. 開啟該資料夾，網址為 `https://drive.google.com/drive/folders/XXXXXXXX`，複製 **XXXXXXXX**（資料夾 ID）。
4. 在 `set-env.sh` 設定並重新部署：
   ```bash
   export FOLDER_ID_FOR_ATTENDANCE_SHEETS=XXXXXXXX
   ```
   部署腳本會把此變數傳給 Cloud Run。之後新建的試算表會建立在此資料夾內，佔用的是該 Google 帳號的 Drive 空間，不是服務帳號的 15GB。

---

**小結**：請盡量提供 LINE 上顯示的**錯誤代碼**與**發生時間**，管理員即可在 GCP Logging 中快速定位並修正。
