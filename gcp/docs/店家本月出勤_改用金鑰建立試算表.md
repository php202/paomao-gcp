# 店家本月出勤：改用服務帳號金鑰建立試算表

當 Cloud Run 的「執行服務帳號」呼叫 Sheets/Drive API 一直回 403，可改讓服務**使用一個有權限的服務帳號金鑰**來建立試算表。

---

## 一、為什麼 403？是金鑰不見嗎？

**不是。** Cloud Run 現在**沒有用金鑰**，用的是「執行服務帳號」（例如 paomao-967）。  
403 是 **Google 不允許這個身分建立試算表**，不是金鑰遺失。

改用金鑰的意思是：**多掛一個「有權限的」服務帳號金鑰**，讓程式用這個金鑰的身分去呼叫 API，有機會避開 403。

---

## 二、整體流程（3 大步）

1. **取得服務帳號金鑰（JSON）**：用一個能建立試算表的 SA，建立金鑰並下載 JSON。
2. **把金鑰存進 Secret Manager**：安全存放，不寫進程式或版控。
3. **部署 Cloud Run 時掛載金鑰**：容器內讀得到金鑰檔，並設 `GOOGLE_APPLICATION_CREDENTIALS` 指向它。

---

## 三、步驟 1：取得服務帳號金鑰（JSON）

### 3.1 選哪一個服務帳號？

- **選項 A**：用同專案裡**另一個**服務帳號（不要用 paomao-967，因為它已經 403）。  
  到 **IAM 與管理 → 服務帳號**，新增一個 SA（例如名稱 `pao-sheets-creator`），或選一個現有的。
- **選項 B**：若你本機有能成功建立試算表的金鑰（例如 `gen-lang-client-0828139766-2a47ceae9dc7.json`），就用**同一個**服務帳號，在 Console 為它**建立新金鑰**（舊金鑰可刪掉），下載 JSON。

### 3.2 給這個 SA 能建立試算表的權限

- 專案已啟用 **Google Sheets API**、**Google Drive API**（你已確認過）。
- 該服務帳號在專案 IAM 至少要有能「用 API」的權限，例如 **編輯者**，或自訂角色裡包含使用 Sheets/Drive 的權限。

### 3.3 建立金鑰並下載 JSON

1. 開啟：**IAM 與管理 → 服務帳號**  
   https://console.cloud.google.com/iam-admin/serviceaccounts?project=gen-lang-client-0828139766  
2. 點選你要用的服務帳號（例如 paomao-967 或新建的）。
3. 上方 **「金鑰」** 分頁 → **「新增金鑰」** → **「建立新金鑰」**。
4. 選 **JSON** → **建立**，會下載一個 `.json` 檔案（**請妥善保存，勿提交到 Git**）。

---

## 四、步驟 2：把金鑰存進 Secret Manager

1. 開啟 **Secret Manager**：  
   https://console.cloud.google.com/security/secret-manager?project=gen-lang-client-0828139766  
2. **「建立密碼」**：
   - **名稱**：例如 `pao-sheets-sa-key`（之後部署會用到這個名稱）。
   - **密碼值**：**整個** JSON 金鑰檔的內容（從 `{` 到 `}` 整段貼上）。
3. 建立完成後，記下**密碼名稱**（例如 `pao-sheets-sa-key`）。

或用指令（金鑰檔路徑請改成你的）：

```bash
gcloud secrets create pao-sheets-sa-key \
  --project=gen-lang-client-0828139766 \
  --data-file=/path/to/your-service-account.json
```

---

## 五、步驟 3：部署 Cloud Run 時掛載金鑰

### 5.1 讓 Cloud Run 能讀取 Secret

Cloud Run 的執行服務帳號要有「讀取該 Secret」的權限：

1. 到 **Secret Manager** 點進剛建立的密碼（例如 `pao-sheets-sa-key`）。
2. **「權限」** → **「新增主體」**。
3. 主體填：**Cloud Run 的執行服務帳號**（例如 `paomao-967@gen-lang-client-0828139766.iam.gserviceaccount.com`）。
4. 角色選 **「Secret Manager 密碼存取者」** → 儲存。

或用指令（請改 `YOUR_SA_EMAIL`）：

```bash
gcloud secrets add-iam-policy-binding pao-sheets-sa-key \
  --project=gen-lang-client-0828139766 \
  --member="serviceAccount:paomao-967@gen-lang-client-0828139766.iam.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"
```

### 5.2 部署時掛載 Secret 並設定環境變數

部署時要把 Secret 掛成**檔案**，並設 `GOOGLE_APPLICATION_CREDENTIALS` 指向該檔案。

**方式 A：用 gcloud 手動更新修訂版本（建議先這樣試）**

```bash
cd /Users/yutsunghan/node_express/gcp
source set-env.sh

# 先照平常方式建映像（若程式沒改可略過）
# ./deploy-line-webhook.sh  會覆寫設定，所以改用手動 deploy 掛 secret

IMAGE="asia-east1-docker.pkg.dev/gen-lang-client-0828139766/gcp-scripts/pao-run:latest"
# 若剛建過映像可沿用；否則先跑一次 deploy-line-webhook.sh 建映像

gcloud run deploy pao-checkin-api \
  --image "$IMAGE" \
  --region asia-east1 \
  --platform managed \
  --allow-unauthenticated \
  --command "node" \
  --args "index.js,serve" \
  --set-env-vars "LINE_STAFF_SS_ID=$LINE_STAFF_SS_ID,LINE_CHANNEL_SECRET=$LINE_CHANNEL_SECRET,LINE_TOKEN_PAOSTAFF=$LINE_TOKEN_PAOSTAFF" \
  --set-secrets "/secrets/sa-key.json=pao-sheets-sa-key:latest" \
  --set-env-vars "GOOGLE_APPLICATION_CREDENTIALS=/secrets/sa-key.json" \
  --min-instances 0 \
  --max-instances 10
```

注意：上面 `--set-env-vars` 只示範必要變數；你實際還需要其他變數（LINE_HQ_SS_ID、PAO_CAT_CORE_API_URL 等）。**最簡單**是：  
先到 **Cloud Run → pao-checkin-api → 編輯與部署新修訂版本** → **變數與密碼** 裡：

- **「參考密碼」**：  
  - 名稱：`GOOGLE_APPLICATION_CREDENTIALS`  
  - 值：選「密碼」→ 選 `pao-sheets-sa-key`、版本 `latest`，**但** Cloud Run 的「參考密碼」是寫進環境變數的「值」，不是掛成檔案。  
  所以要用 **「已掛載的密碼」** 才對。

**正確做法（Console）：**

1. **Cloud Run** → **pao-checkin-api** → **編輯與部署新修訂版本**。
2. **「容器」** 分頁 → **「變數與密碼」**。
3. **「已掛載的密碼」**（或「Volume」相關）：
   - 新增：**掛載路徑** `/secrets/sa-key.json`，**密碼** 選 `pao-sheets-sa-key`、版本 `latest`。
4. **「環境變數」**：新增一筆  
   - 名稱：`GOOGLE_APPLICATION_CREDENTIALS`  
   - 值：`/secrets/sa-key.json`
5. 其餘變數維持不變 → **部署**。

**方式 B：用現成部署腳本（建議）**

已支援選用金鑰掛載。在 **set-env.sh** 加上（密碼名稱請改成你在步驟 2 建立的名稱）：

```bash
export SA_KEY_SECRET_NAME=pao-sheets-sa-key
```

之後照常執行：

```bash
cd gcp && source set-env.sh && ./deploy-line-webhook.sh
```

腳本會自動加上 `--set-secrets "/secrets/sa-key.json=${SA_KEY_SECRET_NAME}:latest"` 並設 `GOOGLE_APPLICATION_CREDENTIALS=/secrets/sa-key.json`。

---

## 六、驗證

部署完成後，在 LINE 再觸發一次「**店家本月出勤**」：

- 若成功，會收到試算表連結。
- 若仍 403，到 **Logging** 搜尋 `createSpreadsheet caller:`，確認 **caller** 是否已變成金鑰對應的服務帳號 email（不再是 paomao-967）。

---

## 七、本機 .env 的金鑰（選用）

你 `.env` 裡的 `GOOGLE_APPLICATION_CREDENTIALS=./gen-lang-client-0828139766-2a47ceae9dc7.json` 是**本機**跑程式時用的；若該檔案不見了：

- **本機**跑「店家本月出勤」或 `scripts/debug-sheets-create.js` 會失敗（找不到金鑰）。
- **Cloud Run** 的 403 與本機金鑰無關；Cloud Run 預設不用金鑰，改用金鑰是照上面「Secret Manager + 掛載」做。

若你要本機也能測建立試算表，請把同一個服務帳號的 JSON 金鑰放到 `gcp/` 底下（檔名自訂），並在 `.env` 設成該路徑（**勿提交金鑰檔到 Git**）。
