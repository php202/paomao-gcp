# LINE「我要打卡」目前還是沒反應 — 檢查清單

依你的畫面：多次「我要打卡」、機器人只回過一次「稍後幫您補打卡 : 系統錯誤404」，之後再傳就沒反應。請依序做下面幾項。

---

## 1. 先修 404（Core API 網址）

**系統錯誤 404** 代表 GAS 打某個網址時「找不到」。通常是 **PaoMao_Core 的 Web App 網址** 錯了或失效。

### 你要做：

1. 開 [Apps Script](https://script.google.com) → 專案 **泡泡貓 員工打卡 Line@**
2. **專案設定**（齒輪）→ **指令碼屬性**
3. 看 **PAO_CAT_CORE_API_URL**：
   - 必須是 **PaoMao_Core** 專案「部署 → 管理部署」裡 **網路應用程式** 那筆的網址
   - 結尾要是 **`/exec`**，不能是 `/dev`
   - 正確範例：`https://script.google.com/macros/s/AKfycby5ibTcUxvPD-Xj1-lOHOJ5oI27CbyyaHv2K3cvNd1PwMiPvwGCpjlzi6UbW4fwip2UaA/exec`
4. 若不對或沒設：到 **PaoMao_Core** → 部署 → 管理部署 → 複製正確網址 → 貼回 **PAO_CAT_CORE_API_URL**
5. 確認 **PAO_CAT_SECRET_KEY** 也有設，且和 PaoMao_Core 一致

---

## 2. 設定 config 備援（避免再打 Core API）

這樣 **getCoreConfig 不再打 API**，就不會再 404、也不會多耗 urlfetch。

1. 在 **PaoMao_Core** 開暫時函式，執行一次：
   ```javascript
   function 複製Config給備援() {
     Logger.log(JSON.stringify(getCoreConfig()));
   }
   ```
   執行後 **檢視 → 執行紀錄**，複製整段 JSON。

2. 在 **泡泡貓 員工打卡 Line@** → **專案設定** → **指令碼屬性** → **新增**：
   - 屬性：**`CoreApi_getCoreConfig_backup`**
   - 值：貼上步驟 1 的整段 JSON（可壓成一行）

---

## 3. 部署最新版 GAS

確認本專案（有備援邏輯）有推到 GAS 並更新部署：

```bash
cd "gas/泡泡貓 員工打卡 Line@"
npm run ship
```

---

## 4. 再測一次「我要打卡」

完成 1～3 後，在 LINE 再輸入一次「我要打卡」：

- 若 **PAO_CAT_CORE_API_URL** 正確 或 **已設 CoreApi_getCoreConfig_backup** → 不應再出現 404，應會出現打卡按鈕或正常回覆。
- 若 **當天 urlfetch 額度已用盡** → 仍可能「沒反應」（無法回覆），需等 **隔日額度重置** 再測。

---

## 5. 若仍沒反應：看 Logs

到 [Google Cloud Logs](https://console.cloud.google.com/logs)：

- 篩選：專案「泡泡貓 員工打卡 Line@」、`doPost` 或 `resource.labels.function_name="doPost"`
- 看最近一筆「我要打卡」的錯誤：
  - **404** → 再檢查步驟 1（Core API 網址）與步驟 2（備援是否有設）
  - **urlfetch 回数が多すぎます** → 額度用盡，等隔日；並確認步驟 2 有設好

---

## 總結（照順序做）

| 順序 | 項目 | 說明 |
|------|------|------|
| 1 | 修正 **PAO_CAT_CORE_API_URL** | 與 PaoMao_Core 部署網址一致、結尾 `/exec` |
| 2 | 新增 **CoreApi_getCoreConfig_backup** | 值 = getCoreConfig() 的 JSON |
| 3 | **npm run ship** | 部署含備援邏輯的版本 |
| 4 | 再測「我要打卡」 | 若額度已 0 需等隔日 |
| 5 | 仍沒反應就查 Logs | 看是 404 還是 urlfetch 額度 |

先完成 **1 + 2 + 3**，再測；若當天額度已用完，明天再測一次。
